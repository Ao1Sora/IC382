# IC382 机器人操作手册

适用版本：2026-11-04 最新导航修复版，Jetson 上 `~/ic382-robot` 的统一控制台。

这份手册以当前代码及当天实机检查为准，替代此前聊天中的分散操作步骤。除特别说明外，下面的命令都在 **Jetson 的终端**输入，不是在 Windows PowerShell 输入。

## 快速选择任务

| 我要做什么 | 操作顺序 |
| --- | --- |
| 移动到地图上一个点 | L选图并定位 → 核对激光对齐 → N → RViz的2D Goal Pose点击拖拽 |
| 对一张桌子三点巡检 | L选场地并定位 → N → Publish Point选桌（或D）→ 控制台P → 每到点实际作业后C |
| 搬动后找回位置 | X停车 → 搬好 → G → 小写移动键低速辅助 → 核对定位 |
| 重新建图 | X → S → 手动驾驶 → 停车 → V → 等Map saved → X → L选新地图 |
| 停止任务 | 点击控制台，按X；导航中空格/k也会取消任务 |
| 启动报已有控制器 | Jetson终端执行 bash reset_robot.sh --start |

## 1. 先认识两个窗口

| 窗口 | 用途 | 在这里操作什么 |
| --- | --- | --- |
| IC382 控制台终端 | 控制机器人、切换模式、选择地图、开始或终止巡检 | 键盘快捷键 |
| RViz 地图窗口 | 看地图、雷达、车体与路径，设置位置、点击选桌、指定导航目标 | 鼠标操作 |

**先点击需要操作的窗口，使它获得焦点。** 在 RViz 里按 `P`、`X`、`i`，不等于向控制台发命令。需要移动、巡检或终止任务时，先点击控制台终端。

无线键盘可以直接连接 Jetson；也可以通过电脑的 VNC 操作同一个桌面。两种方式运行的是同一套程序。

命令键区分大小写。建议保持 Caps Lock 关闭，用 Shift 输入大写命令。大部分快捷键不需要回车；地图菜单确认、`:pose` 坐标输入需要回车。

## 2. 每次开机怎样启动

1. 接通机器人及 Jetson 电源，等待 Jetson 桌面启动。
2. 使用连接 Jetson 的屏幕与无线键盘，或在 Windows 双击项目里的 `Connect-Jetson.cmd` 进入 VNC。
3. 在 Jetson 桌面打开终端，输入：

   ```bash
   cd ~/ic382-robot
   bash run.sh
   ```

4. 等待出现 `IC382 ROBOT CONSOLE`。默认模式是 `MANUAL`，车体保持零速，按移动键才运动。

只启动一份控制台。不要同时再启动旧的 `teleop`、独立底盘 launch 或另一套导航；出现已有底盘/控制器提示时，先退出旧程序，再启动本控制台。

如果控制台已经运行，直接使用现有窗口，不用重新执行命令。

## 3. 先记住停车和退出

| 情况 | 操作与结果 |
| --- | --- |
| 手动或建图中停车 | 控制台按空格或小写 `k`，发送零速 |
| 手动移动键松开 | 最后一次移动键输入后约 0.5 秒超时停车，不是松手瞬间停车 |
| 终止当前巡检、导航或建图 | 控制台按大写 `X`，停止任务、停车，返回 `MANUAL` |
| 导航模式按空格或小写 `k` | 同样会终止导航并返回手动，不是暂停后继续原任务 |
| 回到手动模式 | 大写 `M`，效果同停止当前任务并返回手动 |
| 退出整个程序 | 大写 `Q` 或 Ctrl+C，停车并关闭本程序启动的进程 |
| 地图菜单中的 `X`、空格或 Esc | 关闭菜单；打开菜单时任务已经停止 |

`X` 是取消，不保留可恢复的巡检进度。重新巡检需要再次选择桌子并按 `P`。

关闭 RViz 窗口只会关闭显示，**不会自动终止巡检**。停止任务应使用控制台 `X`；重新打开地图窗口用 `R`。

手动模式没有导航避障。软件停车也不能替代车体的物理急停；发生无法控制的运动时使用车体实际的急停/驱动停止装置。

## 4. 手动移动

确认控制台显示 `MANUAL`，点击终端后使用小写按键：

```text
u   i   o       左前弧线 / 前进 / 右前弧线
j   k   l       左转     / 停车 / 右转
m   ,   .       倒车弧线 / 后退 / 倒车弧线
```

- 长按移动键：连续移动。
- 松开：约 0.5 秒内超时停车。
- 空格或 `k`：立即发送停车指令。
- 初始线速度 0.05 m/s，初始角速度 0.15 rad/s。
- 上限为 0.1 m/s、0.3 rad/s。

| 调速键 | 作用 |
| --- | --- |
| `q` / `z` | 整体速度增加 / 减少约 10% |
| `w` / `x` | 只调整线速度 |
| `e` / `c` | 只调整角速度 |

注意小写 `x` 是降速，大写 `X` 才是终止任务。

`b` 是老师原程序的全向模式切换。当前车体配置为差速底盘 `senior_diff`，正常使用 `NORMAL`，不需要切换到 OMNI。

## 5. 使用已有地图进行巡检：日常主流程

完整顺序：**L 选场地 → 回车自动定位 → 核对定位 → N 启动导航 → 选择点导航或桌子巡检。**

- 点导航：RViz **2D Goal Pose** 点击并拖出目标朝向，松开即发起。
- 桌子巡检：**Publish Point** 选桌 → 控制台 **P** → 每到一点实际完成作业后按 **C**。
- 两种任务互斥，不能同时运行。

### 5.1 选择地图与场地

1. 控制台按大写 `L`。程序停止当前任务并打开地图菜单。
2. 用上下方向键或小写 `j/k` 移动选择。
3. 按回车加载。程序保存选择，启动当前地图的 AMCL 并打开 RViz，无需重启控制台。先用 2D Pose Estimate 手动设置实际位置和朝向，再由小范围雷达匹配持续微调；不会自动做全地图搜索。
4. 按 `Esc` 可以关闭菜单而不换地图，但此前的导航任务不会自动恢复。

菜单状态的含义：

| 状态 | 含义 |
| --- | --- |
| `MATCHED SCENE` | 有可读取的定位地图、导航地图和非空桌号配置 |
| `MAP ONLY` | 有地图，可定位并低速手动移动；尚不能用它执行桌子巡检 |
| `[current]` | 当前选中的地图 |

`MATCHED SCENE` 仅代表文件与配置齐全，**不代表桌子坐标已在当前现场核对，也不代表路线已通过实车验收**。

地图数量以菜单实时扫描为准。已有标注的场地包括 `20261104-165059`、`20261104-184000`；选择与当前真实场地对应的地图，不要仅按日期判断。

当前版本的点导航和巡检共用导航入口，因此都需要 `MATCHED SCENE`；`MAP ONLY` 可测试定位和手动辅助，按 N 会提示缺少导航地图或桌号。

### 5.2 启动导航，同时保留定位

1. 先通过选图自动定位，或用 G 及低速手动移动辅助定位，确认激光与地图对齐。
2. 回到控制台按大写 N。
3. 程序保留现有地图服务器与 AMCL，只增加规划、控制和巡检节点；不会再将定位重置到原点。
4. 等待 RViz 左侧 Navigation 2 面板显示 Navigation、Localization 为 active。重复按 N 不会重启已经运行的导航。

N 只启动软件，不指定目标，因此此时不移动是正常现象。导航模式的小写移动键不控制车体。若需要再次手动辅助定位，按 G 切回定位模式，会结束当前导航任务。

绿色 active 表示节点激活，不代表实际定位已核对。按当前配置，主程序约每秒请求一次雷达与地图匹配；只有扫描新鲜、AMCL 已激活且上次请求结束时才执行。

### 5.3 在 RViz 设置位置与朝向

1. 点击 RViz 窗口。
2. 点击顶部 **2D Pose Estimate**。
3. 在地图上机器人实际所在的位置按住鼠标左键。
4. 朝机器人实际朝向拖出箭头，松开鼠标。
5. 等待定位更新，检查雷达点与地图中的墙面、桌腿等轮廓是否对齐，以及车体图标的位置与朝向是否合理。

对不齐就重新设置，不要仅凭绿色 `active` 判断定位正确。这里设置的是位置估计，不会让机器人驶向所点的位置。

### 5.4 在地图上指定一个导航目标点

当前定位采用 IMU＋轮式里程计提供短时运动估计，AMCL 与小范围雷达匹配负责地图定位。初次启动或重新选图后，先由操作员使用 **2D Pose Estimate** 标定实际位置和朝向。此后每秒只在当前位置附近搜索：平移半径不超过 12 cm、角度不超过 ±6°；只有匹配明确改善时才施加微调，单次最多 6 cm、4°。没有检测到偏差时不反复重设位姿，不自动做大范围重定位。修正先使用同一雷达时间戳的 TF 匹配，再用里程计将结果补偿到发布时刻，避免转向时把旧姿态当作当前姿态。补偿只外推最近 0.2 秒内的短时运动，里程计或 TF 过期时不施加修正。AMCL 的每秒更新请求继续保留，但它本身不代表对齐成功。

控制台新增 `Local scan/map match`：`tracking` 表示局部匹配正常，`locally_corrected` 表示刚施加小修正，`tracking_correction_limited` 表示匹配仍良好、但候选触及微调边界，因此暂不修正且不取消导航，`set_2d_pose_estimate_first` 表示等待手动初始定位。连续出现 `outside_local_range_or_poor_match` 或数据失效时关闭导航运动许可，重新手动对齐后再选择目标。G 仍是显式触发全局搜索的功能，日常小范围修正不需要按 G。

`motion_compensation_unavailable` 表示本轮无法安全把修正补偿到当前时刻，因此跳过本轮修正；导航许可取决于实际匹配健康与传感器看门狗，不因单次跳过修正就取消目标。真正失去匹配、数据过期、操作员重新设置初始位姿仍会停止相应导航。

校准节点由主程序的定位启动组统一管理，每个 ROS domain 只允许一个实例。不要另行后台启动校准节点后再打开主程序。维护重载应先停车、保存当前位姿，使用 `bash reset_robot.sh` 清理旧进程，再通过主程序启动；不保留脱离主程序的校准进程。

RViz 的绿色 `Actual collision footprint` 来自主程序的 `/ic382/body_footprint`，跟随底盘坐标持续更新，避免 Nav2 停止后残留旧位置的绿色框。绿色折线是规划路径，黄色框是桌面标定。

1. 确认定位正确，且控制台显示 NAVIGATION。若不是，先按 N。
2. 点击 RViz 工具栏的 **2D Goal Pose**，不要选 2D Pose Estimate 或 Publish Point。
3. 在允许通行的目标位置按住鼠标左键，拖出希望机器人到达时的朝向，松开左键。
4. 主程序接收目标并检查导航、定位和传感器状态；满足条件后发给 Nav2，机器人开始规划并移动。
5. 观察地图中的路径以及控制台 Status。若显示未就绪、目标拒绝或任务已在运行，目标没有成功发起，应按提示处理。
6. 中途停车：点击控制台，按空格、小写 k 或大写 X。当前实现会取消任务、结束导航并回到 MANUAL，不保留可直接恢复的路径。

更换目标前，先取消旧任务，再启动 N、核对定位并重新选择目标。点导航不会自动执行三点巡检，也不需要按 C。

控制台 `Point navigation finished; status=4` 表示动作报告成功，5 表示取消，6 表示终止失败；失败不等于已到达。机器人到达位置仍需现场核对。

差速车采用带原地旋转运动原语的 State Lattice 规划。普通路线和恢复路线优先保留车体外廓到障碍 0.10 m 的空隙；这是可让步的路线偏好，不是碰撞区。若偏好区挡住通道，会按真实车体外廓重新搜索，并优先选择距两侧障碍更远的中间路线。只有真实车体无法通过才拒绝。路径段和终点旋转仍按真实车体复核，不启用障碍膨胀层。距离实际目标点不超过 0.10 m 后锁定平移，只按最短角度原地转向你指定的精确朝向，不再前后追点；朝向误差进入 0.15 rad（约 8.6°）容差后停车并报告成功。路线偏好与目标位置容差是两项不同设置，实际效果仍受定位误差影响。低速进度检查保持 0.02 m / 60 秒。

RViz 的 `/goal_pose` 只由主程序转为一个导航动作；Nav2 内置的话题直达入口已隔离，避免同一个点击产生两个互相抢占的目标。点导航保留速度上限与停车门控。健康信息失效或主程序授权心跳中断时关闭运动许可；这项检查不能替代你对定位正确性的核对。

绕障恢复：规划或路径跟踪失败时，先尝试沿当前车身后方低速后退 0.10 m（0.05 m/s，单次最多 12 秒）。只有后退返回成功后，才清理传感器障碍层并从新的当前位置重新规划，成功后跟踪新路径。普通和恢复路线均优先采用 0.10 m 空隙，无法满足时允许按真实车体通过并优先居中。最多恢复两次；后退受阻或超时即终止，恢复次数耗尽仍无路也终止。清理障碍层不会删除原始地图、禁行区和桌面。执行过程中不再每秒替换全局路径，避免反复重置终点状态；实时障碍变化导致跟踪失败时会触发上述恢复和重新规划。

低速碰撞预测设为 3 秒，前视距离 0.15 m，避免 5 cm 栅格在 2–5 cm/s 速度下尚未产生前方采样就结束预测。若日志出现 `Starting point in lethal space`，表示当前估计车体与占用区重叠；先核对定位、车体外廓和障碍来源，原生后退恢复可能也会拒绝执行。

| RViz 工具 | 含义 | 是否发运动目标 |
| --- | --- | --- |
| 2D Pose Estimate | 告诉 AMCL 机器人当前大致位置和朝向 | 否 |
| Publish Point | 点击选桌；也可配合终端读取地图坐标 | 否 |
| 2D Goal Pose | 指定机器人要到达的位置和朝向 | 是，松开鼠标后提交 |

### 5.5 选择桌子

二选一：

- **鼠标选择**：RViz 顶部点击 **Publish Point**，再点击带桌号的桌子内部或边缘附近；选中的桌子显示黄色，标签带 `[SELECTED]`。
- **键盘选择**：回控制台按大写 `D`，循环选择已配置的桌号。

黄色桌框表示“当前选择”，不是禁行区编辑结果。点击选桌本身不会启动运动。

### 5.6 执行巡检与到点确认

1. 点击控制台，核对 `Desk` 显示的是要巡检的桌号。
2. 按大写 `P` 发起该桌巡检。
3. 程序只选择当前最近的未巡检候选点，并让 Nav2 从当前实际位姿规划这一段；地图显示当前段路径，不提前计算后续点之间的路径。
4. 到达一个检查点后，任务状态进入 `WAITING_FOR_WORK`，车体停车等待作业。
5. **实际完成当前点的检查作业后**，回控制台按大写 `C` 确认。
6. 程序继续下一点。三个点都完成并确认后，本桌任务结束。

`C` 只是向主程序报告当前点作业已完成，不会替你执行识别、拍照或贴标。无等待作业的检查点时，按 `C` 会提示不能确认。

下一张桌：用 `D` 或鼠标重新选桌，再按 `P`。中途停止：点击控制台按 `X`。

## 6. 机器人被搬动后怎样重新定位

场地没有变化时，搬动车体一般不需要重新建图。

1. 先点击控制台按 X，取消旧任务并停车，再将车体搬好放稳。
2. 确认地图正确；需要换图时按 L 选择并回车，自动开始全局定位。已是正确地图时，直接按大写 G。
3. 等待 AMCL 激活。无需先手动猜测位置，也不需要配置桌号和禁行区。
4. 用小写 j/l 缓慢旋转，或 i/, 小幅前后移动，补充不同视角的扫描与里程计信息。
5. 观察机器人估计位置、朝向和激光是否与真实环境、地图轮廓对应。存在多组候选位置时可继续辅助移动，不能仅凭方差缩小判断成功。
6. 空格或 k 只停车，AMCL 继续定位。定位模式不会在30秒后自动结束；X 才结束整个定位模式。
7. 核对定位正确后按 N，当前 AMCL 会保留。然后使用 2D Goal Pose 点导航，或选桌并按 P 巡检。

定位辅助限速为 0.05m/s、0.15rad/s，松开移动键约0.5秒超时停车。没有移动键时机器人不会自行旋转或探索；定位辅助不提供导航避障。

如果自动搜索仍明显不对，可在定位模式使用 RViz 的 2D Pose Estimate，给一个已知的大致位置与朝向，再由 AMCL 修正。想重新做一次全地图搜索时，松开按键后再次点按 G。

坐标已准确测量时，可输入 `:pose x y yaw` 后回车；x、y 单位米，yaw 单位弧度。Esc 取消坐标输入，Ctrl+C 退出程序。

## 7. 重新建图与保存新地图

完整顺序：**X 停止旧任务 → S 建图 → 手动驾驶 → 停车 → V 保存 → 等待成功 → X 结束 → L 选新地图。**

1. 点击控制台，按大写 `X`。
2. 按大写 `S`，启动雷达、SLAM 和 RViz，控制台显示 `SLAM`。
3. 在控制台用小写移动键缓慢驾驶，让雷达覆盖要导航的区域。尽量经过已走过的位置，帮助闭环。
4. 建图期间不要直接搬动车体；如果地图明显重影或断裂，先停止并检查，而不是继续把错误地图用于巡检。
5. 完成后按空格停车。
6. 按大写 `V` 保存，等待控制台明确显示 `Map saved`。文件保存在：

   ```text
   ~/ic382-robot/maps/时间戳/
       map.yaml             地图描述
       map.pgm              地图图片，实际扩展名以 map.yaml 的 image 字段为准
       scene.yaml           新场地配置
   ```

7. 保存完成后按 `X` 结束 SLAM，再按 `L` 查看或选择新地图。

保存期间不要退出程序；看到 `Saving map` 不等于已经保存成功。保存失败时查看 `save-map.log`。

**新地图默认是 `MAP ONLY`。** 程序不会复制旧桌号、旧桌子坐标或旧禁行区到新坐标系。可以选中并直接测试定位，但要完成下一节配置后才能巡检。

保存地图也不会自动切换当前导航地图，需要用 `L` 明确选择。

## 8. 新地图怎样成为可巡检场地

这一部分目前仍需要人工配置。**当前 RViz 没有画禁行区、画桌子并保存的编辑工具。Publish Point 只负责选桌。**

每套场地文件的职责：

| 文件/字段 | 用途 |
| --- | --- |
| `map.yaml` 与其图片 | 原始雷达地图，供定位使用 |
| `navigation_map.yaml` 与其图片 | 导航专用地图，包含桌面完整投影及其他禁行区域 |
| `scene.yaml` 的 `inspection.desks` | 该地图坐标系下的桌号与桌子多边形 |
| `scene.yaml` 的 `params_file` | 可选的该场地 Nav2 参数覆盖文件 |

### 8.1 手动准备禁行地图

1. 保留原始 `map.yaml` 及其图片。
2. 复制图片为 `navigation_map.pgm`（也可使用支持的其他图片格式），复制 YAML 为 `navigation_map.yaml`。
3. 在图片编辑器中打开复制的图片，将桌面完整投影和其他禁行区域填成占用区域；标准 `negate: 0` 地图通常使用黑色表示占用。
4. 不要裁剪、缩放、旋转图片，不改变像素尺寸。
5. 在复制的 `navigation_map.yaml` 中，将 `image` 改为新图片名；保持原始 `resolution`、`origin`、阈值和 `negate` 一致。

地图显示的黄色桌框不是禁行限制。只有导航地图中实际标成占用的区域才会参与当前静态障碍规划。上层机构可能碰到桌面，因此不能只把桌腿当作桌子的全部障碍。

### 8.2 配置桌号和边界

1. 打开该地图目录下的 `scene.yaml`。
2. `map` 指向该场地的原始地图 YAML；`navigation_map` 指向配套禁行地图 YAML。
3. 在 `inspection.desks` 中填写桌号及桌面多边形顶点。顶点使用 `map` 坐标系、单位米，沿桌边顺时针或逆时针排列；当前程序要求 3–8 个顶点的凸多边形。
4. 保留 `schema_version: 1`，统一控制台使用 `start_hardware: false`，底盘由控制台管理。
5. 保存后，在控制台重新打开 `L` 菜单，重新选择并回车加载这套场地，使修改生效。
6. 加载后先核对定位与桌框是否正确，再按 N 启动导航。

不知道顶点坐标时，可以在第二个 Jetson 终端运行：

```bash
source /opt/ros/humble/setup.bash
ros2 topic echo /clicked_point
```

再用 RViz 的 Publish Point 点击桌面各角，读取输出中的 x、y。点击位置必须结合真实桌面边界核对；低位雷达只看到的桌腿位置不能直接当作整个桌面边界。

修改的是各地图目录的 `scene.yaml`；日常选图使用 `L`。程序会把选中的整套场地复制到运行配置，不需要每次再手改运行配置。

当前车体按雷达中心量取：前 0.10 m、后 0.30 m、左/右各 0.20 m，在 `inspection.laser_body_bounds` 中配置。启动导航时自动根据安装配置的雷达到底盘变换换算 Nav2 的 footprint，不能直接把雷达坐标当作底盘坐标。

`inspection.parking_reference: laser` 和 `parking_distance_m: 0.4` 表示巡检停车目标处雷达中心到桌面边缘为 0.40 m，此时面向桌面的车体前缘名义净距为 0.30 m。每条桌边生成一个候选点，先检查车体是否侵入桌面。每段开始时，程序根据最新实际位姿选择最近的未巡检候选点，再由 Nav2 规划该段并执行避障和恢复。到点停稳、按 C 确认作业后才选择下一点，共完成三个不同点；不提前固定整趟顺序，也不生成后续点之间的路径。40 cm 是目标距离，会受 10 cm 到点容差及定位误差影响；并非全程保持雷达到桌面恒定距离。重新加装机构后需更新外廓。

## 10. 常见问题

### 启动报已有底盘或控制器时的一键复位

在 Jetson 终端执行：

```bash
cd ~/ic382-robot
bash reset_robot.sh --start
```

脚本先发送停车指令，停止当前用户相关的底盘、雷达、导航、SLAM与本项目RViz进程，再重置ROS发现缓存和桌面键盘重复设置；检查通过后启动主程序。地图、scene.yaml和当前场地配置保留，不需要sudo。复位会结束正在运行的机器人任务，地图保存中不要执行。

只复位、不启动：`bash reset_robot.sh`。仅预览进程清单、不清理：`bash reset_robot.sh --dry-run`。日志写入 `~/.local/state/ic382/reset-时间戳.json`。



| 现象 | 检查与处理 |
| --- | --- |
| 按键完全没反应 | 先点击控制台；确认大小写、Caps Lock，以及是否仍在地图菜单或坐标输入中 |
| 点按能动、长按不连续 | 本版启动时会开启 Jetson 桌面按键重复；先停车退出，再重新启动本版控制台。仍异常时再检查桌面键盘重复设置 |
| 按 N 后车体不走 | N 不发目标；核对定位后用 2D Goal Pose，或选桌再按 P |
| 到点等了一会，按 C 后报 journal_ack_timeout | 日志确认计时已修复：只计算尚未确认的新事件的等待时长，不把等待作业的空闲时间算作日志超时；真正落盘确认超过 5 秒仍停止任务 |
| 目标点导航未就绪 | 看 Status 和 Navigation health；等待启动、检查定位与传感器，不要连开多套导航 |
| 工具栏没有 2D Goal Pose | 先在控制台按 R 重新打开项目 RViz；仍无按钮时确认运行的是当前版本 |
| 切换导航后位置曾变成原点 | 旧版本会重启 AMCL；使用当前版重新定位后按 N，原 AMCL 保持运行 |
| 地图可见但激光/车体不更新 | 选图后应自动启动 AMCL；确认非只看旧预览，可按 G 并检查 localization.log |
| 点导航任务未成功到达 | 检查 Status 返回码和 navigation.log；4成功、5取消、6失败，核对定位与目标可达性 |
| 地图菜单只有一项 | 只找到一套有效地图；新地图保存成功后会加入 |
| 新地图不能巡检 | MAP ONLY 尚无配套禁行图和桌号，按第 8 节配置 |
| 地图窗口有机器人，但与现实不符 | 重新做 2D Pose Estimate，检查雷达与地图对齐 |
| RViz 关闭了 | 在控制台按 R；若任务需停止，另外按 X |
| `Inspection server not ready` | 等待 Nav2 启动并查看 navigation.log，不要连续启动多套导航 |
| 按 `C` 提示没有等待作业点 | 当前没有进入 WAITING_FOR_WORK；C 不是启动巡检键 |
| `Map save failed` | 查看 save-map.log；未确认成功前不要把该地图用于巡检 |
| 打开地图菜单后原任务不继续 | L 会取消原任务；重新加载地图、核对定位、N 后再提交目标 |

查看日志：在第二个 Jetson 终端执行，例如：

```bash
tail -n 80 ~/.local/state/ic382/navigation.log
```

| 日志 | 内容 |
| --- | --- |
| `base.log` | 底盘、串口、EKF |
| `lidar.log` | 雷达启动 |
| `slam.log` | SLAM |
| `save-map.log` | 地图保存 |
| `map-preview.log` | 旧版地图预览诊断记录；当前选图会启动定位 |
| `localization.log` | 当前地图服务器、AMCL 全局定位 |
| `navigation.log` | Nav2 规划、控制、停车门控及巡检服务器 |
| `rviz.log` | 地图窗口与模型显示 |

定位显示说明：选图后启动AMCL，手动设置初始位姿后建立map到odom_combined的变换。只加载地图图片而不启动定位，会造成RViz地图可见但激光和机器人位置无法更新。全局搜索初期可能存在多组候选位置，仍需用不同视角扫描或2D Pose Estimate辅助核对。

### 原地转向策略（2026-11-04 更新）

按操作员要求，控制器的路径对齐和终点朝向调整均不再对纯原地旋转执行车体扫掠碰撞预测。转向时线速度为零，角速度仍受限；平移行驶的真实车体检查与碰撞预测保留，定位与传感器看门狗保留。该策略允许车角在转动时进入障碍范围，操作员需要关注实际间距。局部雷达匹配搜索仍为半径 12 cm、±6°，单次校准上限现为 6 cm、4°，不是全地图重定位。
